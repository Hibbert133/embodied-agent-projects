# 独立审计浮点算术修订 v2

首次DEV记录审计停在 `DEV/02/door-open-v3/UNCHANGED/KINEMATIC_RANK_W1.0` 的第64步命令，错误为 `argmin and exact tie`。原始失败日志、首个差异和完整来源计划保留。其BASELINE与X_MINUS分数只差一个float64末位；原控制器采用点积，独立v1采用平方后sum，改变了这处精确并列的排序。所选X_MINUS严格符合实际已冻结点积结果。**这不是任务通过，也不是修改控制器、样本或科学门槛的依据。**

独立v2只把两维平方和的计算从 `np.sum(v**2)` 改为 `np.dot(v,v)`，以核对已定义的有限精度执行语义；仍独立从原始系数构造预测、全部五项分数及argmin，不调用控制器的评分函数。不增加容差，不改变并列规则，不把近似并列改为精确并列。保存选择、命令和消费关系继续精确核对。

冻结的v1控制器、收集器、审计源码、协议、配置、原始记录、模型和原生通过回执全部保持原字节。独立v2文件和只读包装器单列来源。包装器只在本次进程中将冻结记录重放器的 `audit_rank` 全局绑定为明确的v2函数，其他重放／物理顺序／状态／成本检查照原样执行；输出回执明确列有效修订来源和原失败，不把v2运行冒称未修改的v1运行。现有门槛字段中的原始源码哈希仍是被冻结模块的身份，额外有效审计哈希与修订回执必须同时核对。

新增回归测试使用此保存计划及合成数组，检验v1复现原差异、v2接受实际点积选择、错误选择即使只差一个末位仍被拒绝，并核对源码修订仅限两项平方和操作。审计禁止环境创建、重置、推进及网络，实际C4/C8只读复算另计。失败的v1重放和定位扫描的计算成本也分别重建，不抹去失败尝试。
