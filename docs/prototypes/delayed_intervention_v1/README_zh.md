# 中途干预执行组件：隔离原型 v1

该组件把一个已经保存的离散选择落实到当前真实边界之后的动作。它为后续中途干预实验准备执行接口；当前短探测 MAIN 不导入此目录，冻结实现和提交保持不变。

## 已实现的四个动作

| 动作 | 实际行为 |
|---|---|
| `CONTINUE_CURRENT` | 继续使用当前纠正映射。 |
| `SWITCH_SAVED` | 使用调用前已存在的另一份纠正映射；不存在则拒绝。只切参数，不回退状态或时间。 |
| `RUN_UNCORRECTED` | 对当前观测调用同一个固定策略，使用其合法范围内的原始命令。 |
| `STOP` | 不再执行；未成功案例仍保留 500 步截止损失。 |

没有探测、重新拟合、报警阈值或在线 API 选择逻辑。中途测量后更新需要先取得相应辨识资格，不能将当前状态伪装成初始重置状态。这一范围来自[中途干预的数据合同](../../paper/delayed_switch_support_and_next_measurement_20261019_zh.md)。四个动作是执行参考，尚未构成新的获取算法。

## 数据与执行合同

[controller.py](controller.py)接受严格的 `Boundary`：任务、已经完成的步数、39 维当前公共观测及其当前结束状态、当前纠正映射和可选的已保存映射。字典入口拒绝未知字段，包括嵌套的种子、随机状态、扰动真值和未来结果。当前 `success` 是已经发生的可见状态，不是未来任务标签。

`ControllerSnapshot.matrix_xy` 表示**从原始策略指令到发送指令的纠正矩阵**，不是待求逆的执行器估计矩阵。其含义为先截断原始策略指令，再计算平面命令 `C @ u_xy + d`，最后截断发送命令；z 和夹爪分量不作仿射修改。主机须从确实较早保存的纠正记录构造该对象，并在未来实验日志中绑定来源。数值字段符合格式，不等于组件能够认证这些数值的历史来源或物理正确性。

执行时先提交并核对 `CHOICE`，其中包含完整候选映射、映射哈希及选中的动作。之后的实际命令由**确认保存的候选**计算。每步再保存 `COMMAND`，等待主机回传 `StepReceipt`，核对动作前观测、发送命令和累计物理步数，最后保存 `STEP_RESULT`。执行只调用政策、逐步主机和日志三个接口，没有环境构造、重置或随机源操作接口。

一个执行对象只允许一次干预，进入回调前即消耗该权限，避免异常后的重试和回调重入。它从调用时已经消耗的步数接着扣费；500 步总额不重置。成功、终止、截断或预算用尽即停止后续策略查询。已经结束的边界只允许 `STOP`，并保留已确认的任务结果。

## 失败和未知步数

日志回执的内容、类型、序号或时间错误，会在继续执行前失败。若策略输出无效，不调用物理主机。若逐步主机抛出异常，或回传的命令/状态/步数不匹配，执行对象停止，记录 `ExecutionFailure` 快照并禁止再次执行。

物理调用尝试在调用前扣除预算。因此可能出现：已扣费 101 步、最后确认完成 100 步、1 次结果未确认。该差别会明确保留，不会假设失败调用完全没有改变环境，也不会自动重试。如果物理回执已经确认，但结果日志保存失败，则保留已确认完成的步数。

生产主机仍需在动作之前对照自己的权威物理账本，拒绝陈旧边界；不能仅相信调用者提供的计数。日志的持久性与不可变性也由主机负责。格式检查不是恶意回调的安全隔离；进程突然退出、MuJoCo 状态和随机数连续性、跨执行对象的预算及来源资格，需要后续集成审计。

## 已完成的验证

[29 项单元测试](test_controller.py)通过，覆盖三种合法运行选择产生不同实际命令、从非零当前状态连续执行、单步剩余预算、提前结束、停止分母、严格字段、回执篡改、写入失败、未确认调用和单次干预约束。测试中的主机是可控的数值替身，实际发生 32 次替身回调尝试、31 次替身状态转移。

[qualification 入口](qualify.py)另生成四个持久化示例，其中三个运行分支各执行两步，停止分支执行零步。每条示例命令都先写入 JSONL、flush 和 fsync，数值替身再从实际文件读回命令后执行。三个运行分支的第一条平面命令分别约为 `[0.3, 0.1]`、`[0.1, 0.2]`、`[0.2, -0.1]`，产生三个不同的最终位置。示例中的“两步后成功”是人工终止条件，只验证衔接，不能引用为机器人任务成功率。

完整证据位于[合成资格回执](../../../outputs/reproduction_reviews/delayed_intervention_v1/synthetic_v1/receipt.json)、[测试日志](../../../outputs/reproduction_reviews/delayed_intervention_v1/synthetic_v1/tests.txt)、[示例结果](../../../outputs/reproduction_reviews/delayed_intervention_v1/synthetic_v1/example_results.json)及[主机回调记录](../../../outputs/reproduction_reviews/delayed_intervention_v1/synthetic_v1/synthetic_host_callbacks.json)。首轮开发测试曾因替身主机把元组观测与 JSON 列表直接比较而失败；修复序列化比较后才进行本次资格运行，记录在回执中。

在仓库根目录可用下列命令复核。输出目录必须是新的，不覆盖原资格记录：

```powershell
.venv\Scripts\python.exe docs/prototypes/delayed_intervention_v1/test_controller.py
.venv\Scripts\python.exe docs/prototypes/delayed_intervention_v1/qualify.py --output outputs/reproduction_reviews/delayed_intervention_v1/new_review
```

本轮新增机器人环境步、环境重置、API 调用和参数拟合均为零。组件尚未接入 MetaWorld，没有物理连续性资格或任务收益结论。后续需在 MAIN 完整结束后整理正式源码、冻结独立协议，再验证真实干预；不能把这里的合成测试替代该步骤。
