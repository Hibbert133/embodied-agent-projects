及进程生命周期峰值的观测，分别记录，不用磁盘余量、工作集或巨大可用
地址空间冒充可用提交内存。API失败/未知值拒绝启动；观测随时会变，
资源阈值不是预留或安全保证。

保存请求/源码指纹/限额、父子资源观测、开始/结果/退出、完整嵌套异常栈和

## 实现测试与一次真实软件资格

先纯字典/结构/假Popen测试并提交冻结，再一次资格。开发和正式数组检查
都禁止实际子进程、环境或拟合；测试覆盖Win64结构尺寸、页到字节换算、
未知资源拒绝、门槛先于spawn、回执/身份/退出、不重试和只终止拥有的句柄。
原2586项按源码复用；新增检查单列，不把fixture结果数当独立科学样本。
入口固定为scripts/qualify_occam_resources_v1.py的qualify或audit，无机器人参数。
独立audit期间禁用主runner/分类/规格验证、资源读取/计算/门和Popen，
只读取保存字典、源码与回执字节；未来观测、缺失守卫和单位错误均拒绝。

资格固定8个独立软件进程：RETURN 4096、RETURN8192、嵌套构造异常、无回执
退出、忽略停止的短挂起、回执篡改、只读运行时导入核对、RETURN65536。
三次RETURN只分配所列小bytes，不通过实际耗尽内存复现OOM。构造异常
明确标为合成，不能称为原生失败重现或已定位旧唯一原因。
每个普通worker最多10秒，挂起项1秒；运行时核对最多90秒，之后强制
终止等待最多5秒。一次资格最多8个真实worker，无追加或重跑。

软件执行profile：可用提交余量至少512MiB、磁盘64MiB，worker私有提交
上限1GiB；这些只控制无物理worker。另行读取一次拟议科学入口条件：
可用系统及当前进程提交余量均至少4GiB、磁盘4GiB。4GiB是保守工程
前提，不是根据任务收益选择的阈值，也未保证未来任意分配成功。当前
资格不会因此开放物理实验；新采集仍需独立完整协议/种子/成本冻结。

运行时导入项仅从原venv包路径导入已锁定库并验证原版本/文件哈希。
