# 在线 API 参与与论文贡献的边界

本文件是面向持续 CCF A 目标的相关工作与贡献缺口检查，不是新实验协议。当前在线校准实验的源代码、提示词、种子和门槛保持冻结。

## 已有方法与当前工作的位置

| 原始来源 | 已建立的能力 | 对本项目的约束 |
|---|---|---|
| [SayCan](https://arxiv.org/abs/2204.01691) | 将语言模型的任务知识与预训练技能的可执行性结合。 | 让 LLM 从候选技能中选动作，本身不是新的贡献。 |
| [Inner Monologue](https://arxiv.org/abs/2207.05608) | 将执行反馈纳入语言模型的闭环规划。 | 观察—调用—执行—反馈闭环已经有先例。 |
| [Code as Policies](https://arxiv.org/abs/2209.07753) | 语言模型组合感知与控制 API，生成机器人策略程序。 | API 能实际驱动机器人控制是集成证据，不能单独作为方法创新。 |
| [KnowNo](https://proceedings.mlr.press/v229/ren23a.html) | 用 conformal prediction 校准语言规划的不确定性与求助选择。 | 定性理由、数值拟合有效和平均校准误差，都不能直接替代统计保证。 |

以上为针对当前接口定位的原始文献核对，不是完整的新颖性审查。各论文的问题设置、学习过程和保证条件不同，不能直接把其完整系统当作本项目的等预算数值基线。2024–2026 年相关工作及任务导向主动辨识仍需系统排查。

## 本轮可以证明什么

在线校准试验需要证明合法 API 选择在任务结果出现前保存，探测由该选择触发，逐步控制命令使用该选择对应的纠正。这可以验证闭环执行链及软件信息边界。

即使所有任务成功，也必须与同数据仿射、最近邻及动态 OLS 对照。选择了不同方法名称，不代表实际控制发生变化；应同时报告最终纠正向量是否与基线相同。只要强基线已经完成全部任务，成功率就存在上限，不能据此宣称 LLM 增强任务能力。

## 仍缺少的研究证据

1. 明确在哪一类可观测、任务相关的歧义中，额外探测或高层推理能够改变实际行动；参数可辨识不等于行动收益。
2. 同观察权限、同交互预算的便宜确定性方法，以及明确的任务导向辨识/证据有效性对照。
3. 冻结之后的新独立评估，保持失败和停止案例的分母；开发数据用于设计后，不再作为独立确认数据。
4. 超出当前已知正常校准与单个任务的证据，以及与具体既有方法相比的可检验机制贡献。

这些是后续要求，不是已经实现的新方法或自动开放的新种子。后续采集仍须先冻结独立协议，不能改变当前正在执行的试验。
