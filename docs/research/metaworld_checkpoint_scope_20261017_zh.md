# 本机MetaWorld checkpoint的实际范围

这是主实验运行期间的只读代码核对，不改变运行中的程序、库或方法，也不读取
未完成的任务分数。对象为本机已绑定的MetaWorld 3.1.1源码，非其他版本的普遍结论。

`metaworld/wrappers.py` 中RandomTaskSelectWrapper的get_checkpoint保存任务列表、
任务采样开关、包装器随机状态与env_rng_state；get_env_rng_checkpoint保存环境、
动作空间、观测空间与目标空间的随机发生器状态。CheckpointWrapper将此内容
包装成env_id与字典。读取这些实现没有发现其保存当前MuJoCo积分状态或完整
任务／包装器运行状态。因此不能仅因API叫checkpoint，就把它当作完整仿真分叉。

当前强参考采集不调用这些checkpoint接口。它每次执行一次受控初始重置，之后
保持实际环境、噪声与时钟连续。记录的physics_witness仍明确未获完整隐藏状态
资格；本次源码核对不升级任何旧数据、未补拍的状态或历史条件配对的资格。

未来若用同一决策状态收集多分支／多未来标签，需单独冻结评价者状态胶囊：

- 说明MuJoCo积分状态及会在运行中变化的模型参数怎样恢复。
- 覆盖任务状态、上一步观测、TimeLimit与终止包装器、所有相关RNG及政策状态。
- 单列私有执行器噪声带与游标；它们只供评价者分叉，不进入代理输入。
- 独立核对恢复前后状态、相同命令与未来噪声下的连续轨迹，以及恢复／重置费用。
- 用新的已注册人口检验，不重跑旧冻结人口补造缺失的隐藏状态或分支结果。

这些是必要的工程与证据要求，不是新定理或已有完整快照实现。有限个相同轨迹
测试也不能单独证明任意未列出的隐藏状态都已完整覆盖。

另一个只读发现是：set_task在可观测性变化时重建sawyer_observation_space属性，
而构造MujocoEnv时已经传入过一个observation_space对象。这解释了一个可能的
空间声明滞后来源，但本页没有通过额外环境实例证明运行警告的全部来源。
运行中的库不作修改，也不根据此猜测忽略任何真实记录／预算／时钟审计失败。
