# 强被动与历史查询参考的真实连续仿真设计

上一阶段 `a49d2c96bd933a33dfb114df07ee43f25bcaf1d3` 仅通过软件夹具验证，
不包含新的MetaWorld任务结果。本阶段将两条被动参考接入实际运行的仿真主机，
并声明历史查询IVR的输入来源。它完成标准参考的一部分，不作为新算法。

## 明确补齐的比较缺口

历史PASSIVE_RECENT8按协议在无效拟合后停止；新PASSIVE8_KEEP在同一8步
决策时刻拒绝无效更新并继续此前控制器。两者后续缓存可能不同，因此总体
时序差同时含后续历史变化，不能全部归因于当前一次fallback。
PASSIVE64_PERIODIC16_KEEP沿用旧PASSIVE_LINEAR的固定间隔和窗口思路，
每16步用最近至多64个真实响应项更新。较晚无效拟合保留最近已应用的控制器。

TASK_HISTORY_IVR4的当前任务查询分布来自自己较早实际执行过的同任务政策
指令，最多最近64条，再加入当前第4步的一条政策查询，各条等权。仅用过去
已完成单元的实际正常动作；当前前缀探测、未执行查询及当前任务未来均不加入。
失败单元里的实际可见查询也可留作统计输入，它们不成为已验证参数缓存。
每个方法都有同样的自身查询保留权限，不共享别的方法、流或未来指令。

无历史查询时数值应等于原单指令TASK_IVR4；有历史时先平均预测方差，再
计算4到8步的相对降低，不能平均各指令的降低比例。保留原25%与源预测报警、
源参数边界刷新规则。这个经验查询分布受历史政策影响，是GAUGE式IVR的
有限适配参考，不是其完整规划器／验证生命周期，也不估计任务回报或费用。

## 为何这不是新颖性主张

[GAUGE](https://arxiv.org/html/2609.32154v1)已有规划器查询加权获取与再校准；
[ToIA](https://arxiv.org/html/2609.19378v1)已有任务／模型学习联合轨迹设计；
[终端可执行性工作](https://www.biorxiv.org/content/10.64898/2026.06.11.731593v2.full)
已经区分校准精度与后续任务失败。当前的保留逻辑与查询窗口是合理对照，
不能把模块组合或标准矩阵公式当新方法。本设计未穷尽查新。

本阶段先冻结真实主机、所有参考、人口、审计及统计，再一次执行。
新18流属于覆盖三×三因素的开发参考，不承担新算法独立确认或小差异非劣效证明。
不能在本轮结果上调25%、窗口、拟合门槛或选择性删掉故障族。
