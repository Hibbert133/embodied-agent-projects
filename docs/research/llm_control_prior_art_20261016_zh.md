# LLM参与机器人闭环的已有工作与贡献边界

“LLM读取反馈，再让主机控制机器人”已经有多条研究路线，不能单独作为本项目的新贡献。
这里核对的是论文官方页面的摘要范围，尚未完成全文、代码和实验设置的系统比较。

| 已有工作 | 官方摘要支持的范围 | 对本项目的直接约束 |
|---|---|---|
| [Inner Monologue，CoRL论文集2023](https://proceedings.mlr.press/v205/huang23c.html) | 使用成功检测、场景描述等语言反馈调整机器人高层计划。 | “增加反馈、让LLM再次推理”本身不足以区分新方法。 |
| [DrEureka，RSS 2024](https://www.roboticsproceedings.org/rss20/p094.html) | LLM生成奖励和域随机化分布以支持仿真到真实迁移。 | 自动提出校准或物理配置，不能仅凭自动化流程声称首创。 |
| [RobotxR1，CoRL 2025](https://proceedings.mlr.press/v305/boyle25a.html) | 将闭环强化学习用于小型LLM的具身推理与适应。 | 若主张LLM学会更好适应，需要比较交互训练路线并披露训练费用。 |
| [CoRAL，RSS 2026](https://www.roboticsproceedings.org/rss22/p054.html) | LLM设计控制目标、VLM提供物理先验、在线辨识修正参数，并以交互反馈调整目标；还包含成功策略检索。 | LLM与数值辨识分工、物理反馈和策略记忆的组合均不是自动成立的新贡献。 |

这些工作任务、控制权限与训练方式不同，不能直接拼接论文成功率作为本项目的实验基线。
下一步若恢复LLM方法研究，需要先写清楚它获得什么证据、可以选择什么实验，
以及与同信息、同物理预算的非LLM方法相比，增加了哪项可测能力。

本项目历史GLM闭环只证明在线API选择真实驱动了15条“探测—纠正—任务”链路；
14/16任务成功未超过两个16/16的校准基线。当前起步响应资格检验没有API参与，
也没有纠正后的任务结果。这两组证据都不能证明上述贡献缺口已被补上。

核对日期：2026-10-16，北京时间。此表是针对贡献边界的初筛，不是完整相关工作综述。
