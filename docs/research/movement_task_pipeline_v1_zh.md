# 四种移动与纠正方法：名字、实验问题和实现范围

这轮比较回答两个具体问题：先移动到规定位置有没有帮助；在同样的移动
之后，利用移动记录更新纠正有没有帮助。四种方法都沿用固定任务策略，
没有调用 LLM API，也没有训练新的策略。

## 方法名字

可以把问题想成机器人收到“向右走”的指令，实际却向右前方走。纠正器
先调整发给机器人的指令，尽量让实际运动接近任务策略原本想要的运动。
`C8` 是用最开始八步探测数据估计的纠正器，不表示八次 API 调用。

| 方法 | 中文理解 | 移动之后实际使用什么 |
|---|---|---|
| `DIRECT_C8` | 保持最初纠正，直接继续任务 | 保存的 C8 |
| `MOVE_KEEP_C8` | 先移动，再保持最初纠正继续任务 | 保存的同一个 C8 |
| `MOVE_INTEGRAL` | 先移动，利用累积位置误差进行补偿 | 移动过程保存的积分补偿 |
| `MOVE_ARX_KEEP` | 先移动，用整段动作及运动记录重新估计纠正 | 有效时用新的 ARX 估计；普通无效时保留原来的 C8 |

`DIRECT` 是直接继续，`MOVE` 是先执行规定移动，`KEEP` 是保留已有纠正。
`INTEGRAL` 表示累积位置误差的积分补偿。`ARX` 是带外部输入的自回归
模型：用之前的运动变化和已发出的动作预测接下来的运动变化，再根据
真实移动记录估计当前动作映射。它是已有的标准模型，不是 LLM。

三种 MOVE 方法的移动程序完全相同。比较 MOVE_KEEP 与 DIRECT 可以
看移动本身的效果；比较 INTEGRAL、ARX 与 MOVE_KEEP 可以看更新纠正
的效果。主要比较预先定为 ARX 与 INTEGRAL，不能看到结果后再更换。
普通估计无效可以按方法定义保留 C8；软件或记录异常则停止整个收集，
不能假装是普通估计无效继续执行。

## 前瞻性任务比较

具体约束以[冻结协议](../protocols/movement_task_development_v1.md)及
[执行配置](../../configs/movement_task/development_v1.json)为准。
54 个独立组，包含三种任务、不变及变化两种条件、四种方法，共计划
1,296 次实际执行。每次最多 500 控制步，移动也占用这份总预算。
每种方法独立构造环境，仅一次受控初始重置；探测、移动、任务连续运行。
所有成功、失败、停止、早结束案例保留在预先规定的人口中。

样本量使用旧研究的完整配对组差值作方差规划代理。54 组按三个干预时点
分层，每层 18 组；统计重采样保持一个组内六个任务与条件单元完整。
这不保证新比较一定有足够功效，也不允许在看到结果后追加样本。

## 实现与审计

收集器保存命令、响应、决定、实际执行以及四份完整状态见证：初始、
干预边界、移动后决定已保存且任务动作未执行时、最终。记录审计核对
命令先于执行、连续状态与噪声、完整预算，以及三种 MOVE 在同一条件下
是否真的从相同的移动后状态开始任务。

移动估计的数值审计另行构建样本、特征、残差和优化问题，不调用生产端
的移动样本构建或逆拟合函数。统计审计从完整原始案例重新构造组差值、
分层区间和历史费用；文件哈希自洽不能代替这些复算。

软件测试包含一维 MuJoCo 测试环境、纯数值样本和完整统计文件测试。
它们用于验证实现及拒绝错误记录；不属于新种子的 MetaWorld 科学结果。
检查日志及源码哈希保存在
`outputs/movement_task/pipeline_validation_v1/`。最终检查和提交完成前，
收集入口拒绝准备新实验。科学结果需要另外完成一次冻结收集、记录审计、
统计及统计审计，届时另写中文结果报告。

## 结论边界

这是四种固定标准方法的任务比较。历史 ARX 的物理迁移准确性尚未整体
通过资格检验，不能因为其数值复算正确就声称模型准确。本轮直接检验
实际任务效果，并如实记录保留 C8、早结束和失败情况。

本轮没有在线 API 决策，也不证明主动探测选择、额外探测的价值或算法
创新。即使 ARX 的任务结果更好，论文目标的七项要求仍需逐项完成；
没有收益则保留负结果。
