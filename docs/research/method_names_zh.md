# 方法名称的中文解释

共同思路：机器人先试几个小动作，观察指令与实际运动的差别，再决定
是否纠正后续指令。例如想向右走，实际却偏向右上方，就需要估计并补偿偏差。
下面大多是实验配置名，名字本身不表示新算法或效果已经得到证明。

不用先背全部缩写。当前九种方案主要比较：**直接做、先测再做、边做边估计**。

| 当前代码名 | 可以这样理解 |
|---|---|
| NO_PROBE | 直接做：不专门测试，也不纠正动作 |
| ALWAYS8 | 每次重测：每个任务先测试8步，再纠正动作 |
| ALWAYS16_OLD | 旧方法测16步：用旧版估计器，多花一些测试动作 |
| PASSIVE_RECENT8 | 边做边估计：利用前8步正常任务动作；估计不合格就停止 |
| PASSIVE8_KEEP | 前8步尝试更新：估计不合格时，继续用此前控制器做任务 |
| PASSIVE64_PERIODIC16_KEEP | 滚动更新：每16步用最近至多64个响应项尝试更新；不合格就沿用控制器 |
| UNCERTAINTY4 | 先检查旧参数：测试4步，也考虑旧估计的误差；必要时继续测到8步 |
| TASK_IVR4 | 看多测有没有帮助：还估计再测4步能否减少当前动作的不确定性 |
| TASK_HISTORY_IVR4 | 多参考以前用过的动作：把自己较早同类任务的实际指令也纳入上述判断 |

“缓存”只是保存以前成功使用的纠正参数，不是大模型的对话记忆。
有缓存的检查方法先测4步；第一次没有缓存时仍需先测8步。
IVR可理解为“减少不确定性”，不等于已经预测了任务成功率。
PASSIVE64里的64是数据窗口，PERIODIC16里的16是更新间隔，不是额外探测64步。

例如，机器人想向右推，却实际偏向右上方：ALWAYS8先专门试动作再算补偿；
UNCERTAINTY4先看看以前的补偿是否还适用；PASSIVE方法则边推边观察。
这些九种数值参考没有调用在线LLM/API。较早的LLM方法让大模型读取证据、
选择是否探测与使用哪个候选纠正，连续纠正数值仍由主机计算。
判断旧参数是否符合观测，与判断再花4步是否值得，是两件不同的事。

| 名称部分 | 中文意思 |
|---|---|
| PROBE | 探测：执行用于了解系统的小动作 |
| 8 / 16 | 使用8步 / 16步探测数据 |
| POINT | 点估计：用一组参数值描述动作偏差，再计算纠正指令 |
| G / GAUSSIAN | 高斯工作模型：在点估计以外，描述参数不确定性；目前没有可靠性保证 |
| DIRECT | 完成探测和估计后，立即执行任务 |
| KEEP | 继续获得数据，但沿用前一次的纠正参数 |
| UPDATE | 用新增数据重新估计纠正参数 |
| CYCLE | 按预定方向轮流探测，例如正x、负x、正y、负y |
| PASSIVE | 执行任务策略的动作，同时观察；没有专门设计新的探测方向 |
| WIDE | 历史命名的固定探测配置；16步版本每个方向连续4步，CYCLE版本则重复两轮8步探测；幅度以对应协议为准 |
| IDENTITY / NO_CORRECTION | 不添加纠正，继续发送底层策略原本的指令；环境扰动仍存在 |
| JOINT | 联合估计：把整段起步响应放在同一个模型中估计偏差 |
| DROP2 | 估计时去掉最早两步自身的响应项；这两步动作仍实际执行 |
| OLD | 沿用此前校准得到的模型 |
| SAME_DATA | 使用相同一批校准数据，便于比较估计方式 |

例如，**立即执行的8步点估计（DIRECT_POINT8）**表示：先探测8步，
算出一组纠正参数，然后立即执行任务。
**探测16步但保留8步估计（KEEP_POINT8_AFTER16）**表示：先用8步估计，
再探测8步，但执行任务时仍沿用第一次估计。
**循环探测16步后重新估计（POINT16_CYCLE）**则会使用全部16步数据。

| 最初在线API比较中的名称 | 中文意思 |
|---|---|
| 不探测 | 从初始状态直接执行底层策略 |
| 探测不纠正 | 先执行探测，再执行原策略；用于检查探测动作本身的影响 |
| 动态OLS | 普通最小二乘：考虑运动随时间的响应，找出最贴合已观察数据的参数 |
| 校准仿射 | 先用离线校准数据建立映射，再估计“旋转、缩放、方向混合、固定偏移”等动作变化 |
| 同数据最近邻 | 在同一批校准记录中，找响应最相似的例子，借用其纠正参数 |
| LLM / 在线API方法 | 大模型读取当前证据，选择是否探测、使用哪个候选；连续纠正数值由主机计算 |

上一轮静态任务比较可以按下面的中文简称阅读：

| 代码名 | 中文简称和用途 |
|---|---|
| JOINT8 | 联合估计8步：整段8步一起估计，再纠正执行任务 |
| JOINT_DROP2_8 | 少用前两步响应：仍探测8步，检查早期响应项是否有额外帮助 |
| SAME_DATA_POINT8 | 同数据传统估计8步：控制校准数据来源，比较估计方式 |
| OLD_POINT8 | 旧模型点估计8步：原有的便宜纠正基线 |
| OLD_G8 | 旧高斯方法8步：纠正时也考虑参数不确定性；原目标和约束仍保留 |
| OLD_POINT16_CYCLE | 旧模型循环探测16步：多花8步获得信息，再更新纠正 |
| NO_PROBE | 不探测：直接执行任务 |
| IDENTITY_AFTER8 | 探测但不纠正：区分探测动作本身与纠正的影响 |

这些都是本项目的实验标签。JOINT8等使用数值估计与固定底层策略，
这一静态任务比较没有调用LLM；最初的在线API方法在上表单独解释。

较早的辨识资格比较只检查参数估计，当时尚未执行恢复任务：

| 中文名称（代码名） | 在比较什么 |
|---|---|
| 联合使用全部8步响应（JOINT_FULL8） | 用独立名义校准得到起步响应模型，联合拟合8步实际位移 |
| 联合模型只拟合后6步响应（JOINT_DROP2） | 使用同一个模型，但去掉前两步自身的响应项；早期命令的物理影响仍保留 |
| 同校准数据的历史响应模型（SAME_DATA_ARX8） | 换成根据过去动作、位移预测当前位移的ARX模型，控制校准数据来源 |
| 旧校准数据的历史响应模型（OLD_ARX8） | 保留此前使用的ARX模型作为历史参照 |

ARX是“带外部输入的自回归模型”。当前AR2版本需要两步真实历史，
所以8步探测只有第3–8步的响应项参与拟合；前两步仍用于构造后续历史。
比较FULL8和DROP2，是在问“增加最早两步自身的响应项有没有帮助”，
不是在比较8次和6次实际环境交互：它们都实际执行同样的8步。

报告会分别说明：闭环是否真实执行、参数是否估得更准、任务是否完成得更好，
以及是否有方法创新。这四件事不能互相替代。

最新的[旧估计预测检查](../../reports/cross_task_cache_validity_development_v2.md)还使用两个标签：

| 名字 | 简单意思 |
|---|---|
| PLUGIN | 只用旧点参数：把上一次估计的一组参数当成已知，检查新观测是否偏离预测 |
| SOURCE_UNCERTAINTY | 加入源参数不确定性：考虑上一次估计也有误差，给新观测的预测留出相应余量 |

它们检查“旧估计是否能解释新响应”，这轮没有执行缓存复用后的任务。
这里的不确定性是工作近似，未报警也不能证明旧估计可靠。

连续任务序列比较进一步研究：**旧参数什么时候还能用，什么时候值得重新测。**
它按时间顺序保留自己较早成功的参数，属于参数缓存，没有调用在线LLM/API。
这些名称仍是标准对照的实验标签，没有凭名字宣称算法创新。

| 代码名 | 简单中文意思 | 实际规则 |
|---|---|---|
| NO_PROBE | 直接做 | 不探测、不纠正，直接执行任务 |
| ALWAYS8 | 每次重新测8步 | 每个任务都探测8步，再估计纠正参数 |
| ALWAYS16_OLD | 旧方法多测一些 | 探测16步，使用旧版历史响应估计器 |
| STALE | 直接用旧参数 | 有缓存就复用，不主动检查 |
| PERIODIC4 | 每4个任务更新 | 按任务序号每4个任务重新探测，否则复用 |
| PASSIVE_RECENT8 | 边做边观察 | 用前8步正常任务动作估计；信息不足或新拟合无效时停止 |
| CUSUM4 | 异常积累后更新 | 先检查4步，累计异常超过阈值才继续探测到8步 |
| PLUGIN4 | 把旧估计当准数检查 | 检查4步，偏离旧点估计的预测就继续到8步 |
| UNCERTAINTY4 | 承认旧估计可能不准 | 检查时考虑旧参数的估计误差，再决定是否继续到8步 |
| BALANCED4 | 四个方向都检查 | 前4步各试正负x、正负y，需更新时完成均衡8步 |
| TASK_IVR4 | 看更多信息对当前动作有无帮助 | 检查报警，或预计再4步能明显降低当前动作的不确定性，就继续到8步 |

复用类方法首次没有缓存时仍需先探测8步；任务失败／停止后清空缓存。
`4/8/16`通常指动作步数，但`PERIODIC4`的4是任务间隔，
`PASSIVE_RECENT8`的8是正常任务动作数。4步检查后沿用参数并不等于
已经证明参数可靠；`TASK_IVR4`也只看当前一个动作，不是完整任务价值预测。

连续任务实验的完整规则见[冻结协议](../protocols/chronological_cache_reference_development_v1.md)。

后继补充的两条标准被动对照现已完成新开发人口的MetaWorld任务仿真，
完整结果见[九方法报告](../../reports/strong_chronological_reference_development_v1.md)。
它们仍是标准参考，仿真结果不代表真实机器人硬件验证：

| 代码名 | 中文意思 |
|---|---|
| PASSIVE8_KEEP | 前8步正常做任务，尝试更新一次；拟合无效就继续此前的控制器 |
| PASSIVE64_PERIODIC16_KEEP | 每16步尝试用最近至多64个实际响应项更新；无效就保留最近已应用的控制器 |

这里的16是尝试更新的间隔，64是响应项窗口，不是额外探测64步。
它们与历史上“无效即停止”的PASSIVE_RECENT8是不同版本，不能互换结果。
